## Decisions

- 每个方向按首个发送卡形状索引奇偶划分两个互斥分片，合计四个 Worker。分片内保留既有数量下界预处理和可行解构造（这部分会重复），后续均衡/自由搜索覆盖全部根分支。所有分片完成后取最优；单片只有达到全局下界才能提前证明。
- 共享 worker 模块增加实例级任务池；进度消息不释放槽位，完成、错误、取消、超时及构造失败均回收。取消旧批次后忽略其消息。
- 网格最多 16384 块、单轴最多 512 块；按模组规模限制而非固定像素限制。最多绘制 512 张接收卡，超出保留统计。绘图坐标归一化，文案仍显示真实像素。任务最长 30 秒或 250000 个搜索状态；达到限制保留可行解，明确未证明最优。
- JSON 仅允许数据解析，兼容字符串之外的尾随逗号，不执行 JavaScript。支持完整 schemeContent 包装或直接方案对象。字段全部校验后原子更新草稿，失败保留原参数。导入不自动启动搜索。
- 模组数量 0 归一化为 1；网口带载严格使用 receiveCardInventory.cableMaxHeight，即使和其他配置冲突也先识别并由计算校验解释。

## Validation

- 79 项 Node 测试通过，涵盖既有算法与接线回归、两模式两方向分片/串行对照、四任务编排、分片失败不误报最优、旧批次消息隔离、队列取消及各异常回收、JSON 与规模边界。
- 实际附件完整 JSON（包含尾随逗号）解析成功，得到 6720×3780 显示屏、480×270 模组、1×1 接收卡模组上限、10240×10240 发送卡上限、10485760 带载、16 口和 65535 网口带载。
- 浏览器验证自动导入、错误 JSON 保留参数、带载冲突提示、1 亿像素宽输入快速拦截。将测试网口带载调整为 650000 后，常规及自由模式均输出 3 张发送卡、196 张接收卡和 40 根网线；默认参数保持 1/36/4。
- 32×32 个单模组接收卡场景输出 1024 张接收卡，结构图及接线图采用提示占位并保留统计，页面保持响应。
- TypeScript、变更文件 ESLint、Vite 生产构建及 git diff --check 通过。ESLint 通过已安装的 @umijs/fabric 依赖目录解析插件；Vite 仍有既有大体积 chunk 提示。
