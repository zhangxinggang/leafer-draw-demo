## Context

现有链路适合普通编辑场景，但无法线性扩展到百万箱体：

- `generateRect.ts` 创建百万个普通对象，随后一次性 `JSON.stringify` 并写入本地存储。
- Zustand 的 `cmps: Cmp[]` 在新增或更新时会展开、复制大数组，渲染 Map 又保存一份对象引用。
- `RectLine` 为每个箱体创建一个 `Box` 和四个 `Text`，百万箱体约产生 500 万个 Leafer 节点。
- `leafer-x-connector` 为每条连接创建对象，并分别订阅源、目标的属性变化；百万边会产生约 200 万个监听关系。
- 当前 Worker 消息对批次执行全量 JSON 序列化，并在每次消息后导出整个 Leafer 树，这不是可用于交互渲染的离屏流水线。
- 当前图片导出依赖单次 `app.export` 和 1x/2x/3x 像素比。100,000 × 100,000 像素的完整位图含 100 亿像素，仅未压缩 RGBA 内存就约 37.3 GiB。

因此，大场景必须避免“一个逻辑元素对应多个常驻 Leafer 对象”，并避免构建单张完整位图。

## Goals / Non-Goals

### Goals

- 在同一场景加载并总览 1,000,000 个箱体。
- 在基准设备上保持平移、缩放和预览响应，详细指标见性能预算。
- 放大到足够比例时，当前可见箱体显示清晰的现有业务文字，以及可选 SVG/PNG 背景。
- 支持最多 1,000,000 条显式连接边的浏览，并为未来的连接编辑保留数据接口。
- 保持普通场景及现有编辑功能、数据语义和 PNG/JPG 导出不变。
- 导出完整场景的多分辨率图片结果，放大到原始尺度时文字保持清晰。

### Non-Goals

- 不支持 1,000,000 个节点的完全图（约 5000 亿条边）在客户端逐条存储和实时显示。
- 不要求在总览比例同时绘制肉眼不可读的多行文字、图片细节或每个箭头头部。
- 不承诺把 100,000 × 100,000 或更大的完整场景导出为一张普通 PNG/JPG。
- 第一阶段不把全部现有 Leafer 组件重写为 WebGL，也不替换普通场景的编辑器。

## Decisions

### 1. 使用双渲染后端和 Leafer 交互覆盖层

普通场景继续由 Leafer UI 2.3.0 渲染。达到大场景阈值或选择“100 万个箱体”预设时，箱体、文字、背景和连线主体进入 WebGL2 批渲染层；被悬停、选中或正在编辑的少量元素通过适配器实例化为 Leafer 覆盖对象。

```text
业务命令 / 测试预设
        |
        v
分块逻辑数据  <---->  Worker 空间索引 / 排版 / 连接计算
        |                         |
        v                         v
WebGL2 实例化场景层       可见块与图集更新
        |
        +---- Leafer 2.3.0 交互覆盖层（选中/编辑/吸附/标尺）
```

这样既避免百万 Leafer 节点，又复用已经验证过的编辑交互。大场景元素 ID、几何和业务字段仍通过统一适配器暴露给现有命令层。

### 2. 数据采用分块 SoA 与可转移缓冲区

- 几何、样式索引、文本索引、图片索引和连接端点按字段分离（Structure of Arrays），使用 TypedArray 保存。
- 字符串和重复样式进入字典；相同 SVG/PNG 资源只保存一个资源键。
- 数据按固定空间块组织，Worker 构建分层网格或扁平 R-tree，并通过 Transferable/SharedArrayBuffer（满足隔离条件时）传递变化块。
- 只向主线程发送视口内块、聚合摘要和精确命中结果，不序列化全场景 JSON。
- 大批量生成记录为一个可撤销命令或数据集描述符，不把百万条记录复制进每个历史快照。

### 3. 使用屏幕空间 LOD

- **总览级**：实例化绘制全部箱体轮廓/填充；文字、背景细节和箭头头部在不可读时不绘制。密集连线按块聚合或隐藏，并保留数量提示。
- **中间级**：显示可辨认的箱体、共享背景缩略图和抽样/聚合连接。
- **详细级**：只对视口和预取边界内的箱体绘制完整文字、原始 SVG/PNG 纹理和原始箭头。
- LOD 切换带滞回区间，避免缩放边界闪烁；视口外资源采用有界 LRU 缓存。

“全部元素可见”指其几何分布在总览中可被表达；“文字清晰”在箱体具有足够屏幕像素或导出原始层级时满足。

### 4. WebGL2 为默认加速路径

箱体和直线/箭头使用实例化顶点数据，文字使用字形图集（优先 MSDF/SDF 或等价方案），SVG 先栅格化到分级纹理图集，PNG 按需解码和上传。渲染循环只在视口、数据或资源状态变化时刷新。

WASM 预留给空间索引构建、文字布局或瓦片编码等经性能剖析确认的热点；CanvasKit/Skia 仅作为导出或兼容性实验，不作为首发主渲染器，避免额外运行时和内存副本。

### 5. 连接数据与箱体数据解耦

连接边以 `sourceIndex`、`targetIndex` 和样式索引的紧凑数组保存。端点移动时只更新受影响的边段，不为每条边注册两端事件监听。空间索引维护“节点到边”的邻接范围，用于选择、局部重算和视口查询。

性能验收图为 O(N) 边规模：最多 1,000,000 条显式边。若业务未来需要更高密度图，必须使用聚合、边束或服务端分块，而不是完整物化完全图。

### 6. 超清导出使用多分辨率瓦片金字塔

大场景导出以场景原始尺度为最高层，Worker/OffscreenCanvas 逐瓦片复用同一排版和绘制规则。输出 ZIP 至少包含：

```text
manifest.json
viewer.html
tiles/<level>/<column>_<row>.png
assets/（仅在查看器需要独立资源时存在）
```

- 默认瓦片为 512 × 512 lossless PNG，边界使用重叠/裁剪规则避免文字和线条接缝。
- 下采样层从最高层逐级生成，查看器根据缩放只加载当前层可见瓦片。
- 采用流式压缩和有界队列，不在内存中拼接完整位图。
- 文字在最高层按原有字体尺寸重新排版和绘制，不把总览画面放大，因此可读性与原始尺度一致。
- 导出对字体和图片资源设置明确的等待、跨域和失败策略；缺失资源不得静默生成错误结果。

普通 PNG/JPG 和有限区域高倍导出继续使用现有入口。超出安全像素或内存预算时，UI 引导用户使用超清图片包。

### 7. 渐进启用并保留回退

- 大场景后端由功能开关和元素阈值共同控制，测试预设显式启用。
- 初期提供“双渲染抽样对比”，对相同可见区域比较 Leafer 与 WebGL 的几何、颜色和文字。
- WebGL 上下文丢失时尝试重建；失败则保留数据、回退普通模式并提示百万级 SLA 不再保证。
- 任何大场景资源在画布销毁、数据切换和导出取消时必须释放。

## Performance Budget

验收基准环境为 Windows 11、当前稳定版 Chrome、1920 × 1080、DPR 1、至少 8 个逻辑 CPU 核、16 GiB 内存及支持 WebGL2 的集成显卡；实际机器型号、浏览器和驱动版本必须随报告记录。

固定数据集：1000 × 1000 个 100 × 100 场景单位箱体，每个箱体四行现有业务文字；图片测试分别覆盖无图、共享 PNG、共享 SVG；连接测试为最多 1,000,000 条显式边。

- 点击生成到可操作总览：p95 不超过 10 秒，期间 UI 有进度且可取消。
- 预热后的连续 30 秒平移/缩放：帧时间 p95 不超过 16.7 ms，p99 不超过 33.3 ms。
- 平移/缩放输入到首个响应帧：p95 不超过 50 ms。
- 稳态百万箱体场景内存：不超过 1.5 GiB；测试报告同时记录 JS heap 与 GPU/进程内存。
- 进入详细级后，当前视口文字、背景和连接须在 200 ms 内完成渐进细化，交互不得等待全部资源。
- 超清导出期间编辑器仍可响应取消和基础导航，额外工作集内存目标不超过 512 MiB；导出总耗时和输出体积作为报告指标，不设置脱离场景大小的固定上限。

若硬件不满足基准条件，系统仍应功能正确，但性能数值仅作为诊断信息。

## Compatibility and Regression Strategy

- 在大场景改造前固化 Leafer UI 2.3.0 的回归清单和关键截图：矩形、文字、图片、自由线、箭头、连接矩形、路径节点编辑、选择/框选、移动/缩放/旋转、吸附、标尺、撤销/重做、JSON 导入导出、PNG/JPG 导出。
- 普通场景默认不启用新后端，现有组件数据和 API 继续走 `cmpRender`。
- 为大场景适配器增加契约测试，验证同一业务命令在两种后端得到一致的 ID、边界、选择和更新结果。
- 对固定视口进行容差化像素对比；字体采用随测试固定的字体文件，减少环境漂移。
- 构建性能基准页面和可下载报告，CI 执行正确性测试；性能阈值在固定基准机执行，避免共享 CI 机器的噪声造成误判。

## Risks / Trade-offs

- GPU 文字与浏览器 Canvas 文字可能存在轻微抗锯齿差异；通过固定字体、排版指标和视觉容差控制。
- SVG 特性范围过宽；首发需定义支持的安全子集，复杂滤镜可在 Worker 中预栅格化。
- 数万瓦片可能产生较大输出；导出前必须预估文件规模，并支持取消、磁盘空间不足和部分失败处理。
- WebGL 上下文及纹理尺寸受设备限制；图集必须分页，不能依赖单张超大纹理。
- SharedArrayBuffer 需要跨源隔离；未满足时使用 Transferable 双缓冲，功能不受影响但吞吐可能降低。
- 浏览器下载 API 对超大 ZIP 有限制；实现阶段优先使用 File System Access API 流式写入，并为不支持的浏览器提供分卷或服务端导出扩展点。

## Migration Plan

1. 建立固定数据集、性能仪表和 Leafer UI 2.3.0 回归基线。
2. 引入只读的大场景数据层、Worker 空间索引和 WebGL 箱体总览，置于关闭的功能开关后。
3. 增加文字、图片、连接 LOD 和精确命中，再接入 Leafer 活动元素覆盖层。
4. 接入大批量命令、撤销/重做、持久化和流式导入导出。
5. 实现瓦片金字塔导出、查看器、进度与取消。
6. 完成功能/视觉/性能验收后，仅对“100 万个箱体”预设和超过阈值的场景启用；保留一版回退开关。

回滚时关闭大场景开关，普通 Leafer UI 2.3.0 路径和原始数据不受影响。
