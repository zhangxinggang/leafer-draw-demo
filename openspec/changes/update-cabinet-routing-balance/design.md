## Context

本次按用户明确的算法更新目标实现。既有常规算法的数量目标是发送卡、接收卡、网线；新增均衡目标放在接收卡数量之后、网线数量之前。自由模式只取消单根网线的矩形覆盖要求，发送卡仍保持矩形及原有硬件约束。

## Decisions

- 统一目标为 `(S, R, Σrᵢ², C)` 的字典序。固定发送卡数 S 和接收卡总数 R 后，平方和最小等价于方差最小；可行时各发送卡数量差不超过 1。不可均分时继续证明约束内的最小方差。
- 保留 `optimizeCabinetCounts` 三数量求解内核，供常规模式证明最少 S、R 和已有回归使用。常规模式随后固定 S、R，完整搜索均衡分配；旧内核的网线最小值仅作为后续安全下界，不能跳过均衡证明。
- 每个发送卡矩形内部独立求最少接收卡、再最少网线。对固定发送卡分区，额外增加某张发送卡的接收卡不可能改善全局第二目标，因此局部最少接收卡足以用于外层四目标搜索。
- 自由模式完整枚举发送卡内的整数接收卡矩形分区，再在共享边邻接图上精确求解带容量限制的路径覆盖。先构造连续蛇形可行解；若未达到下界，枚举包含首个未分配节点的路径并递归覆盖剩余节点。路径从两端扩展，避免漏掉首节点位于路径中间的方案。相同节点集合及相同两端的路径可合并，已分配网口顺序可消除对称；网线外包矩形不参与带载计算。
- 外层使用第一个未覆盖位置的完整矩形枚举；只按面积、几何采样、相同剩余区域和可加目标执行安全剪枝。自由模式取消面积多重集的分区去重，因为相同面积不保证相同邻接关系。路径求解保留完整几何；断开的剩余连通分量各自需要足够的网口。
- 先输出可行方案，再在可停止的 Worker 中完成证明。行列方向只改变搜索顺序；证明共享必须同时匹配配置、模式和四项目标。
- 自由模式的初始方案也会按每张发送卡的全部接收卡重新构造连续路径，以实际累计带载分段，不沿用常规模式的网线矩形边界。在不增加网线、发送卡、接收卡且不降低均衡程度时采用新路径；完整搜索及最优证明条件保持不变。
- 结构图位于显示屏参数右侧、Tab 上方，改为同坐标正视叠加网格，保留真实宽高比例、尺寸线和图例。结构图及接线图复用 momoDraw 的原生 Leafer App、Rect、Path、Text 和共享连线渲染器。实际接收卡宽高映射到稳定颜色，图例和两类图使用同一映射。自由接线的共享渲染选项让路径经过公共边中点并正交转弯，避免不同尺寸的相邻卡之间的中心直线穿过第三张卡。

## Risks / Trade-offs

完整矩形分区和容量路径覆盖存在指数级最坏情况。复杂参数可能较长时间停留在“搜索中”，保留可行方案和停止按钮；不能用时间上限或启发式结果冒充全局最优。数量回归保留原内核测试，新四目标由独立占用位图穷举验证。自由模式验证器通过模组单元邻接建图、从每个起点枚举单端路径，再求子集覆盖，不复用生产双端路径搜索。

## Validation

- 全量 66 项 Node 测试通过，包括既有数量证明、矩形逃逸、共享连线，以及两种模式的四目标独立穷举；新增共享边/角接触/跳卡审计、四方向异形相邻卡的连线范围检查，以及数量已最优时自由模式仍能跨原网线矩形边界重新分组的回归。
- 新增穷举覆盖 64 组固定随机小配置的两种模式和行列方向，以及 18 组密集网格/端口碎片配置的两种模式；检查每次公开方案合法且目标不退步。
- 40 组中等配置验证两种模式均先及时输出合法可行方案；默认 1920×1080 参数两模式、两方向均完成证明。
- 浏览器核对：10 张接收卡分为 5＋5；3×3 模组、2×2 接收卡上限、两口各带载 5 块时，自由模式为 1 张发送卡 / 4 张接收卡 / 2 根网线，常规模式需 2 张发送卡。
- 自由模式放大图点击网线显示实际 72,000 / 72,000 带载，未错误使用 129,600 的外包矩形面积；独立缩放、键盘切换 Tab 和 390px 窄屏排版已检查。
- 用户反馈修正后复查：3×3 自由模式保持 1 / 4 / 2 且路径只经过邻卡；17×7 示例为 1 / 36 / 3，正视网格位于左侧显示屏参数右边、Tab 上方，390px 窄屏无横向溢出。
- 图例在 1000px 和 390px 视口均与绘图同排且位于右侧；窄屏仅示意图区域横向滚动，页面本身无横向溢出。默认自由模式保持 1 / 36 / 4，网线可跨原分组形成非矩形连续路径。
- 算法生产构建、编辑器 TypeScript、变更 TypeScript/TSX 的 ESLint 与 diff 空白检查通过。Vite 保留既有大体积 chunk 提示。
- 当前环境无 OpenSpec CLI；已按规范手动检查增量结构、完整 MODIFIED 需求和 Scenario 格式，未声称运行 CLI 校验。
